### 1. ccxt PR #31002: Coinbase private WebSocket auth fails for Ed25519 CDP keys before this fix (merged 2026-10-28, not yet in a release)
- **Primary URL:** https://github.com/ccxt/ccxt/pull/31002 (related: https://github.com/ccxt/ccxt/issues/25481; https://docs.cdp.coinbase.com/ JWT auth page)

- **Summary:** The PR says `createWSAuth()` for Coinbase only recognised PEM/`organizations/` keys and always signed ES256, so `watchOrders` "and any private WS channel" failed with "Unsupported key format" for Ed25519 CDP keys. - **Strongest counter-evidence:** one comment in #25481 says Coinbase SDK tests showed "only ECDSA" for consumer APIs; the repo's key type is unknown here (secrets not read); the fill stream is "optional" per the repo's own classification, and hourly REST candles are unaffected. The PR's offline WS auth test was removed before merge.
- **Risks:** none of look-ahead/survivorship; operational risk is silent loss of fill ingestion if the stream auto-disables.
- **Data / cost / licence:** none; ccxt is MIT.
- **Relation to repo:** `services/fills/user_stream_ws.py` (ccxt.pro `watch_my_trades`); ccxt pin 4.5.48; SEEN T10 ccxt rows (#30771, v4.5.88) are a different bug.
