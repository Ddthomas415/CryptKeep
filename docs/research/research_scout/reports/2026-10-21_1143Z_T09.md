### 1. `arch` (bashtage) bootstrap module: Hansen SPA / Reality Check, StepM (Romano-Wolf style), Model Confidence Set, stationary bootstrap, and a version-dependent studentize bug
- **Primary URL:** https://arch.readthedocs.io/en/stable/multiple-comparison/multiple-comparison_examples.html (also https://pypi.org/project/arch/, https://github.com/bashtage/arch/pull/882)
- **Date:** 8.0.0 released 2025-10-21 (latest release). 9.0 changes merged to main Oct 2026, unreleased (PR #952, merged 2026-10-17, "no release date yet").
- **Source type:** docs (repo, PyPI). Reading level: docs pages and PR/issue pages read via summary.
- **Summary:** The standard permissive Python implementation of Hansen's Superior Predictive Ability test (`RealityCheck` is an alias), the StepM stepwise multiple-comparison test, the Hansen-Lunde-Nason Model Confidence Set, and stationary/circular/moving-block bootstraps with `optimal_block_length`. Inputs are per-period loss series against a benchmark, which maps onto CryptKeep's trial ledger if each trial's daily returns are kept. Docs recommend the "consistent" p-value.
- **Claimed effect / data:** method tool, no performance claim. CLAIMED bugs: PR #882 (merged 2026-10-07) says `studentize=True` (the default) had no effect on SPA/StepM in 8.0.0, so default p-values and the "superior" set change after the fix. Issue #879: an interim dev build over-rejected (13-19% size at nominal 5%); 8.0.0 was near nominal (5.5-7.4%). PR #944 (unreleased): MCS wrongly excluded models with p equal to `size`; setting `block_size` after construction was silently ignored; constant loss differentials gave p=0 without warning. Issue #862: `StepM.compute()` crash when all models are selected over two or more rounds.
- **Strongest counter-evidence:** none against the method; the counter-evidence is the tool's own instability across 8.0 and 9.0.
- **Risks:** results depend on library version and block length; SPA tests "any strategy beats benchmark", not that the chosen one does; heavy tails and short histories of new entrants weaken bootstrap accuracy; the repo's own design note says not to substitute a stationary bootstrap in the CMC trending design (`statistical_design_disposition_20261010.md` line 39), so use must respect each pre-registration.
- **Data needed, cost, licence:** aligned daily return series per logged trial (already produced by saved results for some families); free; NCSA licence (permissive).
- **Relation to repo:** no hit for SPA/StepM/MCS; fills the gap between the DSR script (which needs an N) and PBO (not computed).
- **Bounded next step (needs operator approval):** a pre-registered, read-only check that recomputes SPA/StepM on one already-saved family (e.g. the 105-setting neighbourhood in `dsr_btc_eth_trend_20261011` inputs) with a pinned arch version and block length fixed in advance; report both 8.0.0 and the 9.0 fix only if 9.0 is released. No new backtests.
- **Status:** UNTESTED.

### 2. Andrews, Kitagawa & McCloskey, "Inference on Winners" (selection-corrected estimate of the best of K) and the `wincurse` Sharpe adaptation
- **Primary URL:** https://www.nber.org/system/files/working_papers/w25456/w25456.pdf (published version listed on IDEAS: https://ideas.repec.org/a/oup/qjecon/v139y2024i1p305-358..html)
- **Date:** NBER WP Jan 2019, rev. Sep 2021; Quarterly Journal of Economics 139(1):305-358, 2024 (IDEAS listing seen by main scout; journal site not opened).
- **Source type:** peer-reviewed (plus an unreviewed MIT-licensed repo, https://github.com/Thesimpleex/wincurse).
- **Summary:** When the top-scoring option among K is chosen, its estimate is biased upward and normal confidence intervals are wrong. The paper gives median-unbiased estimates conditional on selection and "hybrid" intervals, using the estimated covariance of all K candidates. Correlation among trials enters through that covariance, so no "effective N" count has to be guessed. The wincurse repo CLAIMS to adapt this to Sharpe ratios and to reimplement DSR, Harvey-Liu haircut, SPA and Romano-Wolf; its author says the Sharpe extension is not peer-reviewed.
- **Claimed effect / data:** applications are non-finance (charity treatment arms, neighbourhood targeting); corrected estimates "substantially lower" than naive.
- **Strongest counter-evidence:** none found; no crypto or trading application found in an academic source.
- **Risks:** relies on approximate normality of Sharpe estimates (crypto returns are heavy-tailed and autocorrelated); a 576x576 covariance from a short history is noisy; repo is one person's code.
- **Data needed, cost, licence:** same aligned trial-return matrix PBO needs; free; replication package claimed on Harvard Dataverse (CC0, per repo, unverified).
- **Relation to repo:** addresses directly the open "effective N UNVERIFIED" finding in `discovery_engine_proposal_review_20261016.md` lines 72-82.
- **Bounded next step:** operator decides whether to start storing aligned per-trial daily return series alongside the trial ledger (a bookkeeping change, not a test); then a pre-registered comparison of naive vs selection-corrected Sharpe for one saved family.
- **Status:** UNTESTED.

### 3. López de Prado & Lewis, "Detection of false investment strategies using unsupervised learning methods" (clustering estimate of effective N)
- **Primary URL:** https://ideas.repec.org/a/taf/quantf/v19y2019i9p1555-1565.html
- **Date:** Quantitative Finance 19(9):1555-1565, 2019.
- **Source type:** peer-reviewed. Reading level: abstract only (Taylor & Francis paywall; SSRN copy not checked).
- **Summary:** Clusters the correlation matrix of trial returns to estimate the number of effectively uncorrelated trials, which then feeds the familywise false-positive rate and the DSR. This is the published method behind the "false strategy theorem" practice, and the defensible replacement for the judgement-based "10-15" in the repo's DSR README.
- **Claimed effect / data:** methodological; no empirical claim in the abstract.
- **Strongest counter-evidence:** none peer-reviewed found. Sub-scout notes cluster count depends on distance metric and cluster-number choice; eigenvalue methods from genetics (Nyholt, Li-Ji) are an alternative with no finance validation found.
- **Risks:** few observations per trial makes correlations and hence N unstable; must be computed from the ledger as logged at the time (see López de Prado & Fabozzi below: FDR cannot be identified from kept results alone).
- **Data needed, cost, licence:** the same aligned return matrix; free method; paper paywalled.
- **Relation to repo:** `dsr_btc_eth_trend_20261011/README.md` section 1; review lines 72-82.
- **Bounded next step:** pre-register a fixed clustering recipe (distance, linkage, cluster-number rule) before computing N_eff on any family, so N_eff itself is not tuned.
- **Status:** UNTESTED.

### 4. Crypto data-snooping literature: Anghel 2021 (Reality Check: excess returns "rarely achieved"), with Hudson & Urquhart 2021 and Deprez & Frömmel 2024 as the multiple-testing templates
- **Primary URL:** https://ideas.repec.org/a/eee/finlet/v39y2021ics1544612320304414.html (Hudson & Urquhart: https://ideas.repec.org/a/spr/annopr/v297y2021i1d10.1007_s10479-019-03357-1.html; Deprez & Frömmel: https://ideas.repec.org/a/eee/reveco/v93y2024ipbp858-874.html)
- **Date:** 2021; 2021; 2024.
- **Source type:** peer-reviewed. Reading level: abstracts (Anghel, Deprez); Hudson & Urquhart full text via Hull repository.
- **Summary:** Anghel tests ML and technical rules across many cryptocurrencies with White's Reality Check and frictions, and CLAIMS significant excess returns are rarely achieved, with cross-sectional rule performance related to beta and idiosyncratic volatility, i.e. risk exposure rather than skill. Hudson & Urquhart apply stationary bootstrap plus Bonferroni/Holm/BH/BY to 14,919 rules through Dec 2017. - **Strongest counter-evidence:** the three disagree with each other; Hudson & Urquhart sample ends at the Dec 2017 peak.
- **Risks:** close-to-close fills; old bubble-era altcoin data; BH/BY on highly correlated rules has limited meaning; Anghel full text not read.
- **Data needed, cost, licence:** none beyond prices; free.
- **Relation to repo:** Hudson & Urquhart and Deprez already cited in `crypto_trading_edges_survey_20261013.md` line 17; Anghel and the beta/idiosyncratic-volatility point are new. Relevant to the standing focus: apparent alpha in lower-value top-100 coins may be volatility exposure.

### 6. Rej, Seager & Bouchaud, "How should you discount your backtest PnL?" (overfitting factor from post-hoc tweaking)
- **Primary URL:** https://arxiv.org/abs/1902.01802 (read at ar5iv rendering; see header)
- **Date:** Feb 2019.
- **Source type:** preprint (CFM practitioner research).
- **Summary:** Defines an overfitting factor, expected in-sample over expected out-of-sample Sharpe, arising from tweaking a strategy after disappointing backtests rather than independent trials. Low-Sharpe strategies get larger discounts. Complements DSR, which counts trials but not tweaks.

- **Strongest counter-evidence:** base case assumes every tweak hurts OOS, possibly too pessimistic.
- **Risks:** not crypto; model-dependent.
- **Data needed, cost, licence:** none; free.
- **Relation to repo:** pre-registration practice (57 files mention preregistration) already limits tweaks; this gives a way to price the ones that happen.
- **Bounded next step:** add to pre-registration template a recorded "deviation from registered spec" field; no test.
- **Status:** UNTESTED.

### 10. CPCV vs walk-forward in synthetic markets (Arian, Norouzi Mobarekeh & Seco) and the Bayesian critique of CSCV/PBO (Witzany)
- **Primary URL:** https://papers.ssrn.com/sol3/papers.cfm?abstract_id=4686376 (Witzany: https://www.mdpi.com/2227-9091/9/1/18)

- **Source type:** preprint; peer-reviewed open access.
- **Summary:** Arian et al. compare K-fold, purged K-fold, walk-forward and CPCV on simulated markets with jumps and regime switches and CLAIM CPCV gives lower PBO and better DSR, with walk-forward weakest and most variable. Witzany argues CSCV-based PBO is biased (negative OOS rank drift makes PBO and haircuts conservative) and cannot give the OOS Sharpe of the specific chosen strategy; proposes an MCMC model of the joint return distribution instead.
- **Claimed effect / data:** synthetic only; no numbers in Arian abstract.
- **Strongest counter-evidence:** Arian scores with PBO/DSR, metrics from the same school as CPCV; Witzany's model assumes multivariate normal, no autocorrelation. Gort et al. (arXiv 2209.05559) show low PBO did not predict profit on 10 coins (all strategies lost).
- **Risks:** synthetic-to-real gap; partial reading.
- **Data needed, cost, licence:** none to read; free.
- **Relation to repo:** repo relies on anchored walk-forward (`walk_forward_validation.md`); this is a claim, not proof, that walk-forward alone under-protects. Witzany means a computed PBO would err conservative.
- **Bounded next step:** none beyond lead 9; record as context for any validation-design decision.
- **Status:** UNTESTED.
